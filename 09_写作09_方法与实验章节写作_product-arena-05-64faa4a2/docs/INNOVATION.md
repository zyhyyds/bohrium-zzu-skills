- **新增能力**：从代码/配置/日志抽要素 + 缺口追问闭环。`parameter_table` 每条带 source_file 与 line，`missing_categories` 列出数据集/种子/硬件/软件/基线/重复/划分七类缺口，直接生成追问清单。
- **方法改进**：`reproducibility_checklist` 把版本、环境、命令、种子、数据获取与重复次数固定成清单；参数与正文数值对齐由脚本定位，避免"为了顺畅补数值"。
- **边界**：权限不足或材料冲突标 partial/unknown；限制条件必须落到具体失效场景，不写套话。

## 与基线对照的设计

平台以同一案例分别运行基础 Agent 与加载本 Skill 的 Agent。本 Skill 的可观察增量集中在：六类要素齐全度、参数来源可追溯率、条件一致性、复现清单可执行率、缺口追问覆盖率、补写返工轮次。

增益不是靠文字自述，而是靠 `verification.json` 的确定性检查与 `comparison.json` 中逐项指向真实产物的证据。评审可用同一输入重跑 `scripts/solve.py` 复核这些信号。

## 可复用边界

本 Skill 聚焦一种明确任务，不声称是通用系统；换学科、换文体时需替换术语表/风格规则/字段模板，但锚点、守恒与审计机制保持不变。
